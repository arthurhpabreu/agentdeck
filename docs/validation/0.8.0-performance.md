# Performance validation for 0.8.0

Measurements compare release 0.7.0 (`4356982ed80bacd477e6943c229b00310548fc77`) with the 0.8 implementation on the same Windows computer, headless Edge/Chromium 155 and a 1360 × 900 viewport. Native commands/events are simulated; no provider accounts, paid inference or private notes are used.

The UI fixture contains 22,118,400 bytes of archived conversation text (21.1 MiB), 5/20/50 accumulated sessions and 5/8/8 concurrent synthetic streams. Each measurement verifies that seeded text and Stop controls appear in the actual UI, rather than a second store instance created by development hot reload.

| Sessions | Streams | Typing p95, before → after | Switching p95, before → after | Cancel, before → after | Mounted views, before → after |
| --- | --- | --- | --- | --- | --- |
| 5 | 5 | 160 → 39 ms | 2.76 → 0.52 s | 2.16 → 0.45 s | 5 → 4 |
| 20 | 8 | 215 → 43 ms | 4.28 → 0.57 s | 2.50 → 0.49 s | 9 → 4 |
| 50 | 8 | 164 → 60 ms | 6.24 → 0.79 s | 3.14 → 0.58 s | 9 → 4 |

Typing uses 27 samples per load; switching uses four or eight samples. Cancel is one sample per load. Results include automation and two animation frames, so they are comparative fixture measurements rather than absolute latency guarantees. Single runs do not establish confidence intervals.

A separate fixed test applies exactly 1,000 output events for each 5/20/50-session load. Previously those events caused 1,000 local and native durable-state writes. The new durable projection causes **zero output-triggered durable writes**; confirmed metadata changes continue to save. Synchronous store processing measured 56.1/46.4/67.7 ms before and 6.4/3.6/7.2 ms after. Sub-millisecond percentiles have coarse clock resolution.

The longer UI benchmark also records total native/local calls, renderer CPU and JavaScript heap. Its stream duration changes with action latency; raw event and write totals therefore have different elapsed exposure and are not presented as identical-volume throughput comparisons. Renderer heap/CPU are not native WebView or provider-process memory measurements. Drag, native disk queues and output integrity have separate behavioral tests.

Raw reports are preserved in [the validation directory](0.8.0-performance/v080-ui-before.json), with [UI after](0.8.0-performance/v080-ui-after.json), [fixed-event before](0.8.0-performance/v080-before.json) and [fixed-event after](0.8.0-performance/v080-after.json).

## Reproduce

Start the 0.7 release checkout on port 1421 and the candidate on port 1420, using separate Vite cache directories when sharing `node_modules`. Restart the candidate development server after source edits and keep application source unchanged throughout measurement; hot reload can otherwise create duplicate dynamically imported test stores.

Run `node scripts/benchmark-ui.mjs before` and `node scripts/benchmark-ui.mjs after` from the candidate checkout. Install Playwright Chromium first; add `--edge` to use installed Microsoft Edge. Results and generated synthetic native fixtures go into ignored `.local/benchmarks` paths.

The release gates separately run native Rust tests and Windows/macOS builds. Browser benchmarks do not establish live-provider inference speed or Mac performance. Lossless PTY archives use disk storage; bounded renderer/IPC queues do not make disk capacity unlimited or keep processes alive across an OS restart.
